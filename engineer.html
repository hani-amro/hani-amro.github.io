Wain — UAE event discovery & ticketing

Live demo · no real users · payment simulated
The problem
On every ticket sold, three parties have to be paid out of one amount: the organizer, the platform, and the tax authority. If that split is quietly wrong, nobody notices until the money has already left.
What I built
Every sale writes its ledger entries inside one transaction, and a deferred constraint trigger checks at COMMIT that they sum to exactly zero. A half-written entry cannot be committed — Postgres rejects it, not a code reviewer. Ticket reservation is one atomic conditional update, so twenty simultaneous buyers on two seats produce exactly two winners and no oversell.
What it proves
323 tests passing, 100% branch coverage on the money package as a build gate, and 57 CHECK constraints across 16 migrations. Re-deriving the platform margin from first principles caught a AED 1.90 error per order in my own project brief, which had been counting collected tax as platform profit.
  • 323 tests passing on an actual run (205 in apps/api across 8 files + 118 in packages/money across 6)
    Sourcecd apps/api && npx vitest run && cd packages/money && npx vitest run
  • 100% branch coverage on packages/money — 62/62 branches, enforced as a build gate, not a report
    Sourcecat packages/money/coverage/coverage-summary.json # total.branches 62/62
  • 26% his own launch gate's verdict on his own project: 15 of 57 items met (then 21 after closing six)
    Sourcegrep -c '✅' docs/launch-gate.md # 15 of 57 items met

What this is not: a demo, deliberately. Zero real users, the payment gateway is fully simulated, mail is written to a file and never sent, and the demo data is wiped and re-seeded by cron every day at 03:00 UTC. The repository stays private because its history carries an inventory of a server hosting six client sites that are not mine.

Yasmin — an assistant that counts its own misses

Built and measured · model connection down
The problem
An assistant grounded in a client's own pages has one failure that matters: answering something the source never contained. The check for that failure was itself a string match on the first fifteen characters of a sentence the tenant can edit from their own panel — so the check broke the moment anyone reworded it, and broke silently.
What I built
A refusal sentinel that does not depend on wording, the old text match kept as a verbatim fallback, and a refusal_via column recording which path produced each refusal — so the system counts its own misses instead of assuming it has none.
What it proves
9 of 23 refusals were arriving through the fallback — 39% — while every visible indicator was green and the gate reported no gaps. 198 tests run inside the real Cloudflare Workers runtime.
  • 198 tests across 16 files inside the real Cloudflare Workers runtime. I ran the full suite five times: 198/198 in three, and in two runs under concurrent load one test (test/isolation.test.ts) failed on a 5000ms timeout — it passes when run alone. The count holds; the stability does not.

tenant-guard — a leak that the obvious test cannot see

Code sample, not a product · zero users
The problem
SQLAlchemy's lambda cache keys on the code object and only tracks closure variables. Write the tenant filter as a default argument and the cache cannot see it, so the second tenant is served the first tenant's rows — with no error raised.
What I built
The filter as a genuine closure so the cache rebinds it, and a test that asserts the two tenants' result sets are disjoint. The tempting assertion, len(rows) > 0, passes happily on leaked data — which is how a leak like this survives a green test suite.
What it proves
20 tests passing, one runtime dependency, and a test-to-source line ratio of 0.89. Paired with overfit-stats, 41 tests, which refuses to certify a trading strategy that is statistically indistinguishable from luck.
  • 20/20 tenant-guard tests passing — a live run, not a badge
    Sourcecd tenant-guard && python -m pytest -q # 20 passed in 1.88s
  • 41/41 overfit-stats tests passing — a live run
    Sourcecd overfit-stats && python -m pytest -q # 41 passed
  • 0 releases published to PyPI for either library
    Sourcecurl -s -o /dev/null -w '%{http_code}' https://pypi.org/pypi/tenant-guard/json # 404

What these are not: neither library is on PyPI, so pip install does not work. There is no CI — the badges in the READMEs are static images I wrote by hand. Five commits each, all landed within one hour on 16 August 2026, nothing since. They are code meant to be read, not products.

How I work

Errors are loud

If the system cannot work something out, it says so where you will see it. A silent zero becomes an underpriced quote that nobody catches until it costs money.

AI suggests, code decides

AI reads, sorts and drafts. Prices and payments are calculated by deterministic code — and the code overrules the AI, every time.

Every number shows its work

Each figure comes with its breakdown, so a client can challenge a number instead of quietly deciding not to trust it.

Every system states its limits

What a system cannot do is documented next to what it can. That is what makes the rest believable.

Built with AI, owned by me

The architecture decision is mine, the spec is mine, and the acceptance bar that kills the work or ships it is mine; the model writes the implementation inside those three. I am measured by what runs: deployed, operated, watched — and I take the 3 a.m. page.

The definition of correct

Mine I set the invariant that must never break, and enforce it at the lowest layer capable of enforcing it — the database — not in a comment and not in a code review.

The model's The model writes the migration, the constraint, and the test that turn that rule into working code.

What gets measured

Mine I decided that a safety claim is worthless until it measures itself, so I added a column that counts the fallback path instead of trusting a dashboard that was entirely green.

The model's The model wrote the migration, the computation and the test in minutes — but it would never have asked the question that exposed nine refusals out of twenty-three.

The call to ship

Mine Saying «this does not ship» is my job: a 57-item gate that scored my own project 26% green, and the reason 401 tests missed an outage written into the commit message rather than buried.

The model's The model produces the speed — 137 commits in seven days — and I am the one who puts a seven-job CI gate, 323 tests and a decision record in front of it.

“Can you write code on a whiteboard?”

I will not stand at a whiteboard writing code while implying that is how I work; it is not, and performing it hides the thing I am actually good at. The alternative is stronger and far closer to what you would be buying: hand me a real failure from your system — a log, a stack trace, a slow query — and I will diagnose it out loud: the hypothesis, the command that settles it, and what would disprove it if I am wrong. Or reverse it: open any file in my systems and ask me about any line — why that column is a varchar and not an enum, why that guard lives in the database and not in code review, which limits are proven by a test and which are merely written down. If a line is wrong, I will say it is wrong and say what it should have been. As for the whiteboard algorithm: if passing one is a requirement on your side, I will prepare for it the way anyone prepares for an exam — but the result will tell you nothing about what I hand you in the first week.
